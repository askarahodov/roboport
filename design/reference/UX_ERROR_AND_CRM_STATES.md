# ROBOport — состояния ошибок кабинета и CRM, прототип v0.4

## Состояния клиента

| Ключ | Что показываем | Что обязан обеспечить настоящий backend |
|---|---|---|
| `empty` | нет заявок или устройств | не создавать автоматически связи с чужой историей |
| `loading` | проверка прав | не показывать личные данные до ответа сервера |
| `401` | сессия истекла | повторный вход, очистка приватного кэша |
| `403` | нет прав на документ | скрыть содержимое, метаданные, владельца |
| `404` | заявка не найдена/не видна | не дать перебрать номера чужих заявок |
| `409` | устаревшая смета | потребовать новую версию SENT без переноса старого согласия |
| `safety` | опасное устройство | остановить действие до разрешения инженера |
| `revoked` | связь аккаунта отозвана | отказ на повтор и на прежние документы |

`data-state` в HTML — исключительно демонстрационная имитация, не настоящий HTTP или авторизация. Сообщения не содержат PII, полного серийного номера или токена статуса.

## Семь разделов CRM

`queue` — очередь; `intake` — приёмка; `diagnostic` — запрет небезопасных испытаний; `estimates` — версии смет; `stock` — запрет непроверенной совместимости; `qc` — запрет выдачи при FAIL; `audit` — журнал неизменяемых событий. Роли и фактические запреты обязаны проверяться на сервере.

## Критерии готовности текущего макета

- Оригинальные три контура знака C сохранены.
- Light/Dark/Auto на всех состояниях, тема никогда не меняет права.
- Восемь переключателей показывают соответствующую панель, мобильная ширина 390px не ломает компоновку.
- Семь CRM-вкладок работают как независимые макеты; Safety hold и QC FAIL хорошо различимы.
- Нет настоящего согласия, скачивания, резерва, создания заявки и внешних HTTP-запросов.

До production нужны независимый UX-review, полный WCAG 2.2 AA и screenreader, реальные серверные права на PostgreSQL/локальных сессиях (RBAC + ACL) и юридические release gates.
