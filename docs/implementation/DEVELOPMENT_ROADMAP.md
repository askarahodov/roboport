# Последовательность разработки ROBOport — обсуждаемая очередь

**Это предложенный порядок по зависимостям, а не приказ немедленно выполнять все задачи.** Сначала согласовать структуру/стек/Issues, затем начать реализацию с самой первой Ready-задачи. Номер GitHub Issue — главный идентификатор.

## Этап A — сделать репозиторий воспроизводимым

- **#10**: GitHub Actions + lockfiles + lint/type/test gate. Нельзя считать выполненным, пока не появился зелёный GitHub run.
- **#14**: рабочий handoff выбранного знака C, Light/Dark/Auto, токенов и состояний (не юридическое утверждение).
- **#15**: OpenAPI 3.1 независимый lint + контрактная проверка клиентских ошибок/успеха + generation smoke.
- **#16**: рабочая frontend навигация и build, безопасные заглушки private routes.
- **#17**: сверка FSM/DDL/OAS, ADR по несовпадениям до миграций.

**Гейт A:** CI зелёный; точные команды и lockfiles; контракты и данные однозначны, фронтенд собирается; запрещён фиктивный показ готовности.

## Этап B — база и каталог (первые реальные данные только синтетика)

- **#11**: новый Alembic baseline на disposable PostgreSQL 17, миграции и откат.
- **#12**: завершить публичный read-only каталог и интерфейс (существующие 3 операции не выдумывать заново).
- **#18**: данные моделей, точные варианты и доказанный допуск сервиса, защита от ложной совместимости.

**Гейт B:** API+UI+PostgreSQL интеграционные тесты подтверждены; внешний приём обращений отключён.

## Этап C — аутентификация и жизненный цикл заявки

- **#13**: OIDC и server-side ownership/ABAC на двух синтетических клиентах.
- **#19**: заказ/приёмка/FSM/SAFETY_HOLD и аудит.
- **#20**: immutable сметы и согласие на определённую версию.
- **#21**: склад, P/N и конкурентные резервы.
- **#22**: outbox и повторные попытки без внешней отправки.

**Гейт C:** реальные отрицательные интеграционные тесты авторизации, FSM, склада и двойного согласия; никаких звонков/писем.

## Этап D — цифровые рабочие места

- **#23**: личный кабинет (6 разделов) на настоящем тестовом backend с правами A/B.
- **#24**: CRM (7 рабочих маршрутов), роли, QC FAIL и выдача.
- **#25**: документы/фото через абстракцию хранилища и только потом решение MinIO/S3.

**Гейт D:** end-to-end в двух темах и на мобильных устройствах; server-side BOLA тесты и отсутствие доступа к чужим актам.

## Этап E — системные испытания

- **#26**: интеграционный quality gate, backup/restore, security audit, нагрузка, UX-доступность.
- Дальше отдельно юридическое/коммерческое согласование перед реальными клиентами и публичным развёртыванием.

**Безусловно:** ни один ранний гейт не означает разрешения на production. Нельзя подставлять SQLite вместо PostgreSQL и mock JWT вместо интеграции с IdP. При недоступном PG допустимо выполнять #14/#15/#16, но #11 остаётся заблокированным, не «зелёным».
