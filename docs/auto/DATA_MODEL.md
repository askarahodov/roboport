# Автомобильная модель данных: Vehicle и связь с клиентом

**Статус:** `current-dev` только на синтетическом PostgreSQL 17. Это описание схемы и инвариантов, а не production-регламент обработки реальных VIN/ПДн. Production доступ и реальные доказательства заблокированы до независимого security/privacy/legal/ops gate #119.

## Границы модели

- `auto_vehicle` — отдельная автомобильная сущность. `robot_device` не является автомобилем и не мигрирует в неё автоматически.
- `auto_vehicle_customer_link` связывает существующего `customer` с автомобилем. Связь не является документом о собственности и сама по себе не открывает историю ремонта.
- Заказ-наряд/история принадлежит своему `customer_id`. Новый владелец автомобиля не получает старые `service_ticket`, сметы, файлы или WorkOrder только по VIN либо новой связи.
- У автомобиля могут быть несколько связей с разными клиентами. Запрещено вводить ограничение «один активный клиент на автомобиль»: семейное владение, корпоративный клиент и история смены владельца не сводятся к одному owner.

## Таблицы

### `auto_vehicle`

| Поле | Назначение / ограничение |
|---|---|
| `id` | UUID автомобиля |
| `vin` | Nullable; уникален при заполнении; uppercase 17 символов из разрешённого набора. Regex не доказывает глобальную корректность VIN |
| `make`, `model` | Обязательные нормализуемые подписи |
| `variant`, `model_year` | Дополнительные сведения; год ограничен 1886–2100 |
| `created_at` | Время создания |

### `auto_vehicle_customer_link`

| Поле | Назначение / ограничение |
|---|---|
| `id` | Неизменяемый UUID связи |
| `vehicle_id` | Неизменяемая ссылка на `auto_vehicle` |
| `customer_id` | Неизменяемая ссылка на `customer` |
| `linked_at` | Неизменяемое время предложения связи |
| `verified_at`, `verified_by` | Совместно NULL до независимой проверки; затем однократная фиксация времени и сотрудника |
| `revoked_at` | NULL до отзыва; затем однократная необратимая отметка |

Индексы из `0021_auto_vehicle.py`:

- `ux_auto_vehicle_customer_active`: не более одной активной строки для конкретной пары `(vehicle_id, customer_id)`; после отзыва допускается новая строка той же пары.
- `ix_auto_vehicle_customer_active`: быстрый поиск подтверждённых и неотозванных связей клиента.

Индекс не запрещает другому `customer_id` иметь отдельную связь с тем же автомобилем.

## Переходы состояния связи

Состояние вычисляется по полям, отдельного mutable `status` нет:

| Исходное состояние | Допустимое действие | Результат |
|---|---|---|
| Pending: `verified_at IS NULL`, `revoked_at IS NULL` | Независимая проверка с одновременной записью `verified_at` + `verified_by` | Verified |
| Pending | Отзыв | Revoked |
| Verified | Отзыв | Revoked |
| Revoked | Любая повторная верификация, изменение или снятие отзыва | Запрещено |

Новая строка обязана начинаться в состоянии Pending даже при прямом SQL. После создания запрещено менять `id`, `vehicle_id`, `customer_id` и `linked_at`. Верификация фиксируется только один раз и не может быть переписана или очищена. Отзыв нельзя снять, заменить другим временем или обойти прямым SQL. Запрещены `DELETE` и `TRUNCATE`; повторная привязка создаёт новую строку, сохраняя прежнюю историю.

Эти правила обеспечиваются PostgreSQL trigger в Alembic `0133_auto_vehicle_link_guard`, а не только проверками FastAPI. Миграция не меняет существующие связи, не объединяет клиентов и не затрагивает legacy tickets.

## Доказательство и аудит

- `auto_vehicle_claim` хранит SHA-256 одноразового доказательства и состояние процесса; исходное значение не сохраняется.
- Независимый MANAGER review отличается от автора выдачи proof и от клиента-заявителя.
- `auto_vehicle_claim_audit` и `auto_vehicle_link_intake_audit` — append-only.
- Действующая сессия, роль, object assignment, branch scope, CSRF и актуальная customer link перепроверяются на сервере. Повтор запроса не восстанавливает отозванные права.
