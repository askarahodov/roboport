# ADR-AUTO-001: Strangler Pattern для перехода от роботов к автосервису
Дата: 2026-10-26. Статус: принято для dev, не production. Связанные #107, #109, #112.

## Context
ROBOport уже содержит исполняемые PostgreSQL/Alembic, FastAPI, React, ACL, сметы, склад и тесты. Новый бизнес требует автомобилей, VIN, постов и нарядов. Механическая замена слов роботы на авто была бы ошибкой.

## Options
1. Полная перепись — дороже, теряется защита регрессий.
2. Переименование доменных таблиц — быстрый ложный результат, ломает инварианты.
3. Развитие модульного монолита с новым автосервисным доменом — совместимая поэтапная замена.

## Decision
Вариант 3. Первая фаза — отдельные auto_vehicle и auto_vehicle_customer_link с обязательной подтверждённой связью (verified_at/verified_by), потом защищённый API; старые robot_device и service_ticket остаются. Публичный ребрендинг и ввод ПДн только отдельным release gate.

## Consequences
Временно два домена и отдельные правила перехода. Для каждого среза нужны auth, DB, contract, UI и regression проверки. Версионированный API затем обслуживает web и mobile без дублирования серверной логики.

## Security
Доступ к авто не означает доступ к старой истории; наряд имеет собственного неизменяемого customer. Использование бренда и внешних OEM данных только после подтверждения прав.
