# Автокаталоги 2026 — предварительный выбор

Не воспроизводить защищённые базы конкурента. OEM/aftermarket справочник, локальная номенклатура склада и коммерческие предложения — отдельные сущности. Внешняя интеграция допускается только через лицензированный API.

| Провайдер | Заявленные возможности | Что проверить до договора |
|---|---|---|
| Laximo | OEM/aftermarket, API, применяемость | договор, охват, версии, caching |
| PartsAPI | VIN, кроссы, TecDoc, нормочасы | регион, API-тариф, доступность |
| ABCP | товарные группы, кроссы, API | подписка, права на изображения |
| AutoDealer Catalog | схемы, VIN/Frame, возможный API | отдельный договор, права данных |

Материалы для проверки договорных условий: https://doc.laximo.ru/ ; https://partsapi.ru/docs ; https://www.abcp.ru/catalogs ; https://autodealer.ru/catalog . Условия лицензий, тарифы, источники данных и их актуальность на октябрь 2026 **не подтверждены**. Никаких scraping, реальных VIN/ПДн и коммерческих справочников без разрешения.

## Реально работает: offline fixture (current-dev, #231)

Модуль `apps/api/roboport_api/auto_parts_provider.py` определяет независимый Python `PartsCatalogProvider` с методами `find_vehicle`, `search_by_oem`, `list_alternatives`, `get_applicability`, `get_assemblies`. `FixturePartsCatalog` не совершает сетевых запросов, возвращает только синтетическую запись `SYN-001`, всегда `UNKNOWN` применяемость и пустые аналоги/узлы. Синтетический VIN `1HGCM82633A004352` служит исключительно тестовым примером, не подтверждением связи автомобиля/детали.

Каждая выдаваемая запись содержит `provider`, `source_revision`, timezone-aware `retrieved_at`, `brand`, `article`, `applicability` (`VERIFIED` / `UNVERIFIED` / `UNKNOWN`). Одна только cross-ссылка не повышает статус до `VERIFIED`. Поля provenance обязательны; неполная карточка отклоняется.

Невалидный VIN или номер детали даёт `INVALID_INPUT`; неизвестный корректный VIN — `NOT_FOUND`. Нет подходящих деталей/аналогов — пустой tuple, **не** подтверждение применяемости. Провайдер обязан явным образом сигнализировать `RATE_LIMITED` (429), `UNAVAILABLE` (timeout/сбой), `LICENSE_REQUIRED`; при ошибках fixture не возвращает частичные данные. Это модель доменных исключений, **не опубликованные HTTP-коды**.

Проверка без сети: `PYTHONPATH=apps/api python -m pytest -q tests/contract/test_auto_parts_provider.py`. Задача не меняет DDL, auth или публичные URL.

## Планируется (#111, #115)

Лицензированные online адаптеры, adapter sandbox, HTTP OpenAPI, проверенная применяемость и отдельный поток предложений поставщиков — **planned**, не current. Автомобильный интерфейс кладовщика для этого провайдера ещё не существует; реальные действия в UI не документируются как готовые. Перед выводом функции пользователю необходимы контрактный security-review, лицензия, scoped tenant ACL и release gate #119. Внешняя цена, наличие и ETA никогда не означают совместимость с автомобилем.


## Проверяемая граница ответов провайдера (current-dev, #233)

Модуль `apps/api/roboport_api/auto_parts_boundary.py` предоставляет чистые функции `parse_provider_part`, `parse_provider_parts`, `provider_error`. Это **не сетевой клиент, не публичный API и не доказательство наличия лицензии**. Используется исключительно при будущей интеграции после legal/security gate.

Нормализация запрещает пропуск обязательных полей `provider/source_revision/retrieved_at/brand/article/applicability`, принимает только корректную ISO-дату с timezone и один из явных статусов. Любая неверная карточка отвергает **весь** batch; предел batch — 1000 записей. Для данных cross-поиска `VERIFIED` принудительно понижается до `UNVERIFIED` — совпадение номера само по себе не является доказательством применяемости. При 429 возвращается `RATE_LIMITED`, 401/403 — `LICENSE_REQUIRED`, 404 — `NOT_FOUND`; timeout и все прочие коды дают `UNAVAILABLE`. Внешние response bodies, URL и токены никогда не включаются в исключения.

Проверка: `PYTHONPATH=apps/api python -m pytest -q tests/contract/test_auto_parts_boundary.py`. Интеграция с внешним клиентом, аутентификация запросов, аудит прав и UI **planned** в #111 и #115, не являются частью #233.


## Коммерческие предложения поставщиков — offline contract (current-dev, #235)

Модуль `apps/api/roboport_api/auto_supplier_offer.py` валидирует **исключительно синтетические snapshot-данные** предложения поставщика и не совершает сетевые запросы. `SupplierOffer` неизменяемый, содержит `offer_id`, `supplier_id`, `source_revision`, `quoted_at`, `expires_at`, `currency`, `unit_purchase_minor`, `available_quantity` и `article`. Время должно иметь timezone; срок окончания строго позже времени предложения. Цена закупки хранится в целочисленных minor units без float; цена продажи, VAT, статус применяемости и складской остаток **не входят** в контракт. Нулевое количество означает отсутствие доступного предложения, но не остаток на нашем складе.

`parse_supplier_offer` отклоняет пропущенные или лишние поля, неверные типы, отрицательные суммы и количество. `parse_supplier_offers` атомарно отклоняет всё содержимое при неверном элементе, повторе пары supplier/offer ID или пакете более 1000 элементов. Пакет не создаёт резерв, покупку либо заказ поставщику, не доказывает совместимость с автомобилем и не авторизует доступ к чужим предложениям.

Для offline-проверки: `PYTHONPATH=apps/api python -m pytest -q tests/contract/test_auto_supplier_offer.py`. Реальные подключения, проверка ISO валют по правовым/бизнес-правилам, курсы обмена, tenant ACL, котировки, закупки, ledger, PostgreSQL и пользовательский интерфейс — **planned** в #115/#168 и требуют отдельного integration/security/legal gate. Ни одна текущая инструкция кладовщика не должна утверждать, что эти операции уже доступны через UI.


## Инвариант метаданных каталога (#111)

Модель `CatalogPart` отказывает в создании карточки, если `provider`, `source_revision`, `brand` или `article` не являются строками, пусты после удаления пробелов или превышают 160 символов. Эти проверки действуют и при прямом создании объекта синтетическим/будущим адаптером, а не только при разборе внешнего JSON. Типы, дата источника и `UNKNOWN`-применяемость не подтверждают легальность подключения или совместимость детали; online API и production gate остаются `planned`.


## NHTSA vPIC — ограниченный VIN adapter (current-dev, #111)

В `apps/api/roboport_api/auto_nhtsa_vin.py` добавлен `NhtsaVinDecoder`: отдельно от каталога OEM/аналога он использует официальный `DecodeVinValues/{VIN}?format=json` и возвращает только VIN, марку, модель, год и источник `NHTSA-vPIC`. Никаких данных об оригинальных номерах деталей, применяемости, цене, владельце машины или праве на историю он не возвращает. Интерфейс не опубликован в HTTP/UI. Вызовы реального API не выполняются в CI; тесты используют injection поддельного транспорта.

При невалидном VIN возвращается `INVALID_INPUT` до сети; частичный результат NHTSA — `NOT_FOUND`, timeout/некорректный JSON/5xx — `UNAVAILABLE`, 429 — `RATE_LIMITED`. Ответ ограничен по размеру, сетевой timeout ограничен 10 секундами. Нельзя выдавать результат американского vPIC за гарантированную идентификацию автомобиля для РФ, подтверждение владельца или совместимость запчастей.

Официальная документация: https://vpic.nhtsa.dot.gov/api/ и https://vpic.nhtsa.dot.gov/api/home/index/faq . Сервис публичный и бесплатный без регистрации; возможны автоматические ограничения трафика, массовые выгрузки не выполнять. Проверка: `PYTHONPATH=apps/api python -m pytest -q tests/contract/test_auto_nhtsa_vin.py`. Для production tenant ACL, consent, rate limiting, UX и gate #119 ещё не выполнены.


## Универсальная OEM sandbox boundary (#111, current-dev)

`apps/api/roboport_api/auto_oem_sandbox.py` содержит `OemSandboxAdapter` с внедряемой функцией `transport(kind, article)`. Это проверяемая **граница для тестового ответа**, но не реальный HTTP-клиент и не договор с PartsAPI.ru или plan.parts. Без credentials и проверенных условий поставщика реальные запросы не выполняются. Каталожные ответы обрабатываются через `parse_provider_parts`; при `alternatives` даже входной `VERIFIED` понижается до `UNVERIFIED`. Пустая выдача не превращается в доказательство отсутствия или совместимости детали.

`INVALID_INPUT` отклоняется до вызова провайдера; 429 → `RATE_LIMITED`, 401/403 → `LICENSE_REQUIRED`, timeout/5xx и неверный batch → `UNAVAILABLE`. Внешние URL, bodies и secrets не попадут в сообщения доменных ошибок. Проверка: `PYTHONPATH=apps/api python -m pytest -q tests/contract/test_auto_oem_sandbox.py`.

**Остаётся planned:** согласовать лицензию и тарифы PartsAPI.ru/plan.parts, реализовать реальный авторизованный HTTP transport с tenant ACL/rate-limit, sandbox-контрактные тесты с доступом провайдера, UI и legal gate #119. Это не production OEM-поиск.


## PartsAPI.ru: тестовый лимит 50 запросов в сутки (#111, 30.10.2026)

Владелец продукта получил тестовый ключ и сообщил лимит **50 запросов в сутки**. Имя GitHub Actions Secret: `PARTSAPI_TEST_KEY` (значение не хранить в коде/Issues/логах). **Обычные CI PR/push, offline tests и сборки не обращаются к PartsAPI и не тратят квоту.** Никакого автоматического ежедневного расписания или retry внешнего API.

Официальный [getCrosses](https://partsapi.ru/method/doc/getCrosses) описывает поля `brand`, `partNumber`, `crossBrand`, `crossNumber`; [getApplicability](https://partsapi.ru/method/doc/getApplicability) требует `sku` и `brand`. Описанные на публичных страницах подписки платные; тестовый доступ не является правом на production или массовое копирование. Правила сервиса запрещают парсинг.

**Реализовано (offline):** `auto_partsapi.py` нормализует `getCrosses` без выдуманных данных, фиксирует `source_revision` и timezone-aware `retrieved_at`, назначает кроссам `UNVERIFIED`. `DailyRequestBudget` даёт атомарный локальный предел до 50 операций (или меньший для ручного smoke). Этот объект **не является суточным счётчиком между процессами, CI runs или перезапусками**. Его нельзя подключать к реальному HTTP без общего персистентного счётчика и fail-closed резервирования, учитывающего все запуски и уже потраченные запросы в кабинете. До готовности такого механизма live API вызовы из приложения и CI **отключены**.

Тесты: `PYTHONPATH=apps/api python -m pytest -q tests/contract/test_auto_partsapi.py`. Никакие токены или реальные VIN не нужны.

**Далее:** проверить в кабинете фактическую форму запроса (endpoint, параметры авторизации, JSON envelope), условия хранения данных и текущий остаток лимита; по возможности оформить письменное подтверждение от PartsAPI. Только после этого реализовать отдельный явно разрешаемый single-call smoke со счётчиком; полноценный tenant-scoped HTTP/UI, лицензию и release gate #119 не считать завершёнными.


## Персистентный лимитер PartsAPI на одном хосте (#111)

`auto_partsapi_quota.PersistentDailyBudget` сохраняет резервирование вызовов в SQLite-файле; `BEGIN IMMEDIATE` сериализует процессы, использующие **один и тот же файл**. Каждый `reserve(observed_used=число_из_кабинета)` фиксирует один запрос **до** возможного HTTP, включая неуспешный запрос. Перезапуск процесса не обнуляет счётчик. При недоступности файла — `UNAVAILABLE`, при превышении квоты — `RATE_LIMITED`. Часовой календарь в коде — UTC, но реальное время сброса лимита PartsAPI ещё нужно подтвердить у сервиса. Пока лимит сбрасывается по другому часовому поясу, **нельзя использовать резервирование для настоящих запросов без дополнительного согласования**.

Граница безопасности: это **не распределённый механизм** для нескольких контейнеров/хостов и не учёт запросов из кабинета/других инструментов. Значение `observed_used` должно соответствовать актуальному числу вызовов PartsAPI, проверенному вручную перед запуском; его нельзя слепо передавать как 0. Пустой, ephemeral или `:memory:` путь не годится. Сервис не совершает HTTP и не читает `PARTSAPI_TEST_KEY`; live calls в CI по-прежнему выключены. Тесты: `PYTHONPATH=apps/api python -m pytest -q tests/contract/test_auto_partsapi_quota.py`.

Для полноценного production/CI-вызова нужны общая многопроцессная и межхостовая квота, точный reset-time, контракт авторизации и envelope, одобрение юридических условий и gate #119.
