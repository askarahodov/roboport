# Заказ поставщику по дефициту WorkOrder — БоксРитм (synthetic dev)

> **Состояние:** `current-dev` только в закрытом HTTPS loopback с PG17, флагом `ROBOport_SYNTHETIC_AUTO_API=1`, действующим WAREHOUSE/MANAGER object grant. **Нет настоящего EDI, покупок, поставщика, инвойса, права на OEM fitment, денежных операций и обязательств по доставке.** Production и реальные VIN/ПДн запрещены до #119. Операционная задача #443, связь с #115/#168/#111.

## Цель и расчёт дефицита

Для одного **действующего, не отменённого** `WorkOrder`, одной `SKU` и партии филиала сотрудник WAREHOUSE указывает количество, необходимое для исполнения. Сервис берёт свободный остаток `max(on_hand-reserved,0)` под блокировкой SKU и рассчитывает `orderedQuantity=desiredQuantity-available`. При `orderedQuantity<=0` заявка отклоняется: фантомную закупку без дефицита сделать нельзя. Связь WorkOrder ↔ SKU ↔ lot ↔ организация ↔ филиал проверяется **в PostgreSQL и API**, а не только по полям браузера. Повторная попытка создать параллельный заказ на тот же WorkOrder+SKU не приводит к двум заказам.

**Сравнение предложений:** в `/staff/warehouse-supplier-orders` введите минимум два разных тестовых поставщика, их предложения, цену в целых копейках RUB, доступное количество, плановый срок в днях и ревизию источника. Выберите одно предложение. Модель `SupplierOffer` не подтверждает применяемость/OEM/владение автомобилем; это **ручная непроверенная offline fixture**, не авторизованный PartsAPI/OEM-каталог. `quoted_at`, `expires_at`, `delivery_days`, `source_revision` и полный snapshot сравнения фиксируются в неизменяемом заказе. Истёкшая цена, неверная статья, поставщик без нужного количества → отказ 409/422; валюта вне RUB не допускается в этом потоке.

## Действия сотрудников

1. Сотрудник с WAREHOUSE grant своей организации/филиала открывает `/staff` → **«Заказы поставщикам (dev)»**. Введите UUID **синтетических** организации, филиала, WorkOrder, партии и артикул; требуемое количество. Сопоставьте предложения A/B (копейки, доступность, сроки); нажмите **«Создать заказ поставщику»**. Полученный `orderId` означает лишь тестовую документную заявку; складские остатки **не** изменены.
2. Нажмите **«Обновить заказы»**, выберите соответствующий заказ в списке. Статус различает `orderedQuantity`, `documentedQuantity`, `acceptedQuantity`, `valuedQuantity`, `outstandingQuantity`, `canceledQuantity`. Ответ доступен только по своему tenant/branch grant, no-store.
3. При пришедшей части поставки укажите количество не больше outstanding и номер тестового документа, нажмите **«Принять частичную поставку в черновик»**. В одной транзакции создаются `auto_stock_receipt_document` и неизменяемая связка с supplier order; **запас не увеличивается**, пока другой MANAGER не примет приход.
4. **Другой MANAGER** переходит в `/staff/warehouse-receiving`, находит документ в очереди и нажимает **«Подтвердить приёмку»**. После принятия количества отдельно фиксирует закупочную стоимость и НДС. PostgreSQL **проверяет закупочную цену/валюту/ревизию/время цены** по выбранному неизменяемому предложению; изменить цену проведённого документа нельзя. Физический stock ledger, оценка и supplier order lineage не смешиваются.
5. Повторите шаги 2–4 для второй/третьей частичной поставки. На каждой операции новый `Idempotency-Key`, но **при неизвестном ответе** используйте **«Повторить с прежним ключом»** для **того же тела**. Если документ уже создан, повтор возвращает тот же идентификатор без второго увеличения остатка.
6. Если поставщик не довёз остаток, выберите заказ, отметьте **«Подтверждаю отмену только непоставленного остатка заказа»** и нажмите **«Отменить непоставленный остаток»**. Уже созданные документы остаются в истории, но новый приход по закрытому заказу запрещён. Нельзя отменить весь заказ «задним числом» с удалением принятых партий.

## Роли, ошибки и запреты

| Результат | Как трактовать |
|---|---|
| 401/403/404 | Не авторизован, нет WAREHOUSE/MANAGER роли, грант отозван, неверная компания/филиал/объект. Не подставлять чужие UUID |
| 409 | Нет дефицита, конкурентный заказ, просроченное предложение, перепоставка, отменённый заказ, конфликт ключа/цены, несогласованный склад |
| 422 | Некорректная схема, неверная валюта/UUID/количество/дата/цена, отсутствует `Idempotency-Key` |
| 503/сеть | Результат POST неизвестен: повторить **дословно** прежний payload с тем же UUID-key, не создавать второй документ |
| Отзыв роли или сессии | Следующий запрос проверяет полномочия заново. Видимое старое меню или URL ничего не разрешают |
| Реальные платежи/поставщики | **planned**, выполнение запрещено до #119; эта цена — synthetic provenance, не бухгалтерская себестоимость и не кредиторская задолженность |

При наличии двух конкурентных приходов по одному order сервер сериализует по строке purchase order; сумма созданных документов никогда не превышает `orderedQuantity`. Конкурентное изменение источника цены после проведения запрещено immutable DB trigger. Два WAREHOUSE-сотрудника не могут обойти независимое MANAGER подтверждение прихода.
