# Синтетический склад и блокировки PostgreSQL (#21)

Срез работает **исключительно** через localhost HTTPS при `ROBOport_SYNTHETIC_ACCESS_API=1` и disposable PostgreSQL. Не предоставляет доступа к реальным SKU и устройствам.

## Инварианты

- Резервируется только подтверждённое совпадение `part_number + model_variant + region + revision` с полями устройства, связанного с заявкой. Неизвестная или отозванная совместимость → отказ до изменения остатков.
- Требуется живая сессия, роль `STOCK`, объектная выдача `stock.reserve`; отмена и повтор также перепроверяют доступ.
- Резерв использует `SELECT stock_lot ... FOR UPDATE` и проверяет `available_qty - reserved_qty >= qty`. Инварианты PostgreSQL дополнительно запрещают отрицательные значения.
- Отмена уменьшает `reserved_qty`, но не `available_qty`. Повторная отмена другого ключа не создаёт второго движения.
- `inventory_receipt` хранит fingerprint намерения и успешный ответ в одной транзакции. Внешний повтор возвращает результат только после живой проверки авторизации. Хеш не содержит cookie/секретов.
- `stock_movement` и `inventory_receipt` append-only; `audit_event` фиксирует резерв/отмену.

## Lock order / конкуренция

1. Получить actor из живой сессии и проверить ACL.
2. Взять `app_user FOR UPDATE` для сериализации одинаковых ключей пользователя.
3. Для резерва — `service_ticket FOR UPDATE` и `stock_lot FOR UPDATE`, затем атомарно обновить счётчик, создать резерв и movement.
4. Для отмены — сначала `stock_lot FOR UPDATE`, затем строку резерва `FOR UPDATE`, затем освобождение.
5. Весь unit of work транзакционный. Ошибка откатывает и счётчик, и ledger, и receipt.

Тест двух независимых PostgreSQL-соединений резервирует последнюю единицу одновременно: только один успех, один конфликт, зарезервированный остаток равен 1.

## Зависимости и границы готовности

**BLOCKED: #18, #17, #15** — каталог подтверждения совместимости пока не может гарантировать реальные доказательства допуска/два согласования. Синтетический `verified` на лабораторных строках **не является** готовой проверкой поставщика или OEM. До завершения каталога нельзя включать реальные P/N или заявлять production readiness.
