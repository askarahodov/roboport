# Outbox заказов и смет — #22

Внутренний синтетический контур ROBOport. **Не отправляет email/SMS, не обращается к Kafka или внешним провайдерам.**

## Атомарность

PostgreSQL-триггеры `AFTER INSERT/UPDATE` для `service_ticket` и `estimate` создают строки `notification_outbox` **в той же транзакции**, что и бизнес-изменение. Откат бизнес-транзакции удаляет и несохранённое outbox-событие; невозможно зафиксировать одно без другого. Сохраняются только `aggregate_id`, тип события, версия и состояние — без PII, адресов, телефонов и содержимого документов.

Event key уникален по агрегату, версии и состоянию. Для уже доставленных строк запись не повторяется. В пилоте нет гарантий доставки во внешние сервисы, поскольку внешнего транспорта нет.

## Worker / конкурентность

`claim_one()` выбирает подходящие `PENDING` записи через `FOR UPDATE SKIP LOCKED` и переводит их в `PROCESSING`; попытка увеличивается атомарно. Одновременно два воркера не захватывают одну строку. Каждое подтверждение ограждено парой `claimed_by + attempts`, поэтому старый воркер не может подтвердить задачу после истечения аренды и перехвата.

`synthetic_notification_delivery` имеет PRIMARY KEY по `outbox_id`. Вставка синтетического эффекта и переход в `DELIVERED` происходят **в одной транзакции**. При разрыве до коммита оба откатываются, и запись остаётся доступной для повторной обработки после истечения lease. Для настоящей email/SMS отправки понадобится идемпотентность на стороне провайдера: этот модуль не заявляет exactly-once доставку во внешнюю сеть.

## Retry и dead-letter

- Первый сбой → 2 секунды, затем 4, 8, 16 секунд между попытками (минимум, управляемый `available_at`).
- Не более **5 попыток**, затем `DEAD`; ручная диагностика в БД по `last_error`.
- Если пятый worker умер после захвата, lease-reaper переводит просроченный `PROCESSING` с `attempts=5` в `DEAD`.
- Прежние worker после потери lease не имеют права выполнить effect: сравниваются `claimed_by` и номер попытки внутри транзакции.

## Доказательства

Команда: `PYTHONPATH=apps/api python -m pytest -q tests/integration` на одноразовой PostgreSQL 17. Отрицательные тесты охватывают rollback, атомарный insert/update, двух параллельных воркеров с двумя независимыми соединениями, переполучение после crash, fencing, backoff, предел попыток, нулевые сетевые доставки и защиту от двойного эффекта.

Миграция `0017_outbox` наследует `0016_inventory`; GitHub Actions дополнительно выполняет полный `alembic upgrade/downgrade/reupgrade` и `pg_dump/pg_restore`. Рабочий контур остаётся synthetic-only до отдельного release-gate.
