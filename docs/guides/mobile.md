# Мобильное приложение

> **Статус: planned / инструкция ещё не применяется.** Сведения ниже — проектный план, а не перечень работающих кнопок. В dev используйте только синтетические данные.

## Для кого

Клиент iOS/Android. Доступ к каждой операции должен проверяться по активной сессии, роли и конкретному объекту.

## Какие задачи появятся

Установка приложения, вход, мои автомобили, записи, уведомления, сметы, приватность и работа без сети.

## Что реально доступно сейчас

Нативные приложения, push-уведомления и отдельный мобильный authentication flow пока не созданы; нельзя выдавать web-cookie dev-сессию за production mobile auth.

## Подготовка пользовательской инструкции

После реализации соответствующего экрана будут добавлены точный путь по меню, названия кнопок, необходимые права, пошаговые действия, результат операции, диагностика типичных ошибок (401/403/404/409), безопасные скриншоты и версия проверки.

**Зависимости:** #117, #118, #124. [Текущая карта продукта](../auto/PRODUCT.md) · [правила актуальности](../DOCUMENTATION_POLICY.md) · [индекс ролей](INDEX.md).

**До релиза:** запрещены настоящие VIN, телефоны, клиентские документы и платёжные данные в dev-стенде.

## Предлагаемая архитектура и ограничения MVP

См. [ADR-AUTO-002](../auto/ADR-002-MOBILE.md) (proposed / planned). Вход через системный браузер, отдельная native-сессия, защищённое хранилище credential и удалённый отзыв — только проект. MVP предполагает online-only доступ к автомобилям, записям, заказам и сметам; без offline-изменений, сохранения приватных файлов или реальных push. При потере сети/проверки прав будущий клиент должен скрывать приватные данные. Биометрия не заменяет серверную проверку или юридическое согласие. Отдельные iOS/Android инструкции появятся после device E2E и #119.
