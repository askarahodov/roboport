# Кладовщик и закупщик

> **Статус: current-dev только для инвентаризации; остальные складские и закупочные сценарии planned.** Запрещены реальные складские данные.

## Для кого

Кладовщик или специалист по снабжению. Доступ к каждой операции должен проверяться по активной сессии, роли и конкретному объекту.

## Какие задачи появятся

Поиск OEM/aftermarket, подбор аналогов с подтверждённой применяемостью, проверка остатков, резервирование, закупки, выдача и возвраты.

## Что реально доступно сейчас

Автомобильный каталог и внешние поставщики не подключены. Нельзя считать каталог 2026 или его цены достоверными без лицензированного провайдера и проверки применяемости.

## Подготовка пользовательской инструкции

После реализации соответствующего экрана будут добавлены точный путь по меню, названия кнопок, необходимые права, пошаговые действия, результат операции, диагностика типичных ошибок (401/403/404/409), безопасные скриншоты и версия проверки.

**Зависимости:** #111, #115, #123. [Текущая карта продукта](../auto/PRODUCT.md) · [правила актуальности](../DOCUMENTATION_POLICY.md) · [индекс ролей](INDEX.md).

**До релиза:** запрещены настоящие VIN, телефоны, клиентские документы и платёжные данные в dev-стенде.


## Инвентаризация партии — доступный synthetic dev UI (#168)

Откройте пункт **«Инвентаризация (dev)»** верхнего меню (`/staff/warehouse-stocktake`). Работает лишь при локальной synthetic API и действующей сессии; это не производственный склад. Для подсчёта нужна роль WAREHOUSE выбранного филиала. Введите UUID организации, филиала, партии, фактическое неотрицательное количество и причину. Нажмите **«Сохранить подсчёт»**. На экране появляется UUID подсчёта, однако остатки ещё не изменены.

Для второго этапа **другой сотрудник** с ролью MANAGER того же филиала входит в собственную сессию, указывает тот же филиал и UUID подсчёта, затем нажимает **«Утвердить корректировку»**. При успешном ответе создаётся неизменяемый журнал утверждения; расхождение корректирует общий и партийный остаток атомарно. Самостоятельное утверждение собственного подсчёта запрещено даже при двух ролях. Утверждение может вернуть 409, если партия изменилась между подсчётом и проверкой; потребуется новый пересчёт.

**Ошибки:** 403 — сессия/CSRF/роль отозваны или нет доступа к филиалу; 409 — конфликт остатков или уже применённый запрос; 422 — неверные UUID/количество/причина. При потере ответа UI блокирует новый запрос и показывает **«Повторить с прежним ключом»**, чтобы не удвоить операцию. При смене организации/филиала прежний ожидающий запрос очищается. Проверка E2E: `apps/web/e2e/warehouse-stocktake.spec.ts`.

Нет поискового списка партий, оформления приходных документов, коммерческой себестоимости, реального производства, серийных номеров, мобильного сканирования и расчёта НДС. Остальное остаётся planned в #168/#115; перед production обязателен gate #119.


## Список партий филиала (current-dev, часть #168)

На странице **«Инвентаризация (dev)»** после ввода UUID организации/филиала нажмите **«Показать партии»**. API `GET /api/v1/dev/auto/organizations/{org_id}/stocktake/lots?locationId={loc}&limit=30` возвращает не более 30 партий с артикулом, кодом партии/ячейки, размещённым остатком, общим физическим остатком SKU и резервом. Доступ имеют только действующие WAREHOUSE или MANAGER данного филиала; чужая организация не раскрывает список. Кнопка **«Выбрать партию»** подставляет UUID для подсчёта; при наличии следующей страницы используется непрозрачный для пользователя UUID курсора `afterLotId` (только текущий филиал). При отзыве прав экран показывает «Нет доступа к партиям этого филиала» и очищает прежний список. Отсутствие партий, загрузка и ошибка соединения обрабатываются отдельно. Реальный production доступ остаётся выключен.
