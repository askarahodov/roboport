# База знаний БоксРитм — роли

> **Статус: частично current-dev / частично planned.** Это карта актуальных закрытых synthetic dev-инструкций и будущих руководств, а не документация готового автомобильного продукта. Текущий рабочий ASGI регистрирует автомобильные dev API; исторические robot HTTP-маршруты выведены из live runtime и сохраняются только в изолированных регрессионных тестах. Robot SQL-данные и архивный draft OpenAPI **ещё не выведены из эксплуатации**: необходимы проверка восстановления, независимый review и разрешения #165/#119. На закрытом синтетическом стенде доступны отдельные автомобильные endpoints и страницы `/account/vehicles` и `/account/auto-orders`, однако **готового публичного автомобильного кабинета пока нет**. Не вводите реальные клиентские данные.

## Проверенная карта доступности по роли

| Роль | Сейчас на синтетическом стенде | Что не работает как production |
|---|---|---|
| [Администратор](administrator.md) | `/staff/auto-admin`: журнал назначений и отзывов для ADMIN организации | bootstrap, полноценная настройка организации и сотрудников |
| [Мастер-приёмщик](intake.md) | `/staff` → «Автомобили (dev)»: pending-link и код; `/staff/auto-calendar`: synthetic запись; `/staff/auto-order-services`: услуги WorkOrder; `/staff/auto-workshop-qc`: неизменяемый synthetic осмотр | юридическая приёмка, production наряд и документы; dev-запись уже есть |
| [Кладовщик](warehouse.md) | `/staff/warehouse-stocktake`: инвентаризация; `/staff/warehouse-receiving`: synthetic приход; `/staff/warehouse-supplier-orders`: **тестовый заказ по дефициту WorkOrder и частичные приходы**; `/staff/warehouse-work-orders`: выдачи по WorkOrder; `/staff/auto-demo-close`: закрытие резерва заказа | реальные коммерческие закупки, оплата поставщикам и бухгалтерский учёт |
| [Руководитель](manager.md) | `/staff` → «Автомобили (dev)»: проверка связи; `/staff/auto-estimates`: synthetic сметы; `/staff/auto-execution`: запуск работ; `/staff/auto-demo-close`: условная сверка и технический пакет | полноформатные KPI, управление СТО |
| [Клиент](client.md) | `/account/vehicles`: тестовое подтверждение; `/account/auto-booking`: synthetic сценарий записи; `/account/auto-orders`: история только своих нарядов, согласие по последней смете и просмотр технического пакета | самостоятельная запись, реальная оплата и юридические документы |
| [Механик](mechanic.md) | `/staff/auto-execution`: факт работ/получение деталей/завершение; `/staff/auto-workshop-qc`: независимый QC | выполнение ремонта, полная диагностика, выдача |
| [Бухгалтер](finance.md) | **Нет рабочего автомобильного сценария** | деньги, фискализация, документы |
| [Мобильное приложение](mobile.md) | **Нет рабочего приложения** | iOS/Android |

Эти маршруты предназначены только для закрытого dev-стенда. Для доступа нужна действующая сессия и права на конкретный объект/филиал; UUID не подтверждает доступ. При `403` не обходите права другим идентификатором; при `409` проверяйте состояние операции и повторяйте только по документированному безопасному сценарию. Для всех сценариев запрещены реальные ПДн, VIN и платежи. Независимая ручная QA-приёмка и production gate #119 ещё не пройдены.

## Как должна выглядеть инструкция

**Роль → Предусловия → Экран → Шаги → Ожидаемый результат → Ошибки/действия → Права → Проверено на версии.** Названия кнопок и ссылок должны совпадать с текущим интерфейсом, примеры — только синтетические.

Техническая документация находится в [общем индексе](../INDEX.md); правила актуальности — [DOCUMENTATION_POLICY.md](../DOCUMENTATION_POLICY.md). Состояние отключённых маршрутов и архивного SQL проверяйте по [реестру legacy](../auto/LEGACY_ARCHIVE.md), а не по старым робототехническим руководствам. За разработку пользовательской базы знаний отвечают [#123](https://github.com/askarahodov/roboport/issues/123) и [#124](https://github.com/askarahodov/roboport/issues/124), публикация — [#125](https://github.com/askarahodov/roboport/issues/125).

## Доступная dev-инструкция по подтверждению автомобиля

Для QA и разработчиков доступно описание **закрытого синтетического процесса**, но не готовое руководство для реального автосервиса: [подтверждение автомобиля](../auto/VEHICLE_OWNERSHIP.md). Ролевое подтверждение в dev не эквивалентно production bootstrap; самостоятельное внесение реальных автомобилей, юридически значимые подписи и фактическая выдача остаются `planned` до #119.
