# База знаний Airmatik Pro Service — роли

> **Статус: частично current-dev / частично planned.** Это карта актуальных закрытых synthetic dev-инструкций и будущих руководств, а не документация готового автомобильного продукта. Текущее приложение продолжает обслуживать тестовую робототехническую предметную область. Существуют закрытый синтетический read-only endpoint и тестовая страница `/account/vehicles` («Автомобили (dev)»), однако **готового публичного автомобильного кабинета пока нет**. Не вводите реальные клиентские данные.

Инструкции создаются **только после появления соответствующего рабочего сценария**; каждую инструкцию сверяют с конкретным UI, backend ACL и E2E.

## Проверенная карта доступности по роли

| Роль | Сейчас на синтетическом стенде | Что не работает как production |
|---|---|---|
| [Администратор](administrator.md) | `/staff/auto-admin`: журнал назначений и отзывов для ADMIN организации | bootstrap, полноценная настройка организации и сотрудников |
| [Мастер-приёмщик](intake.md) | `/staff` → «Автомобили (dev)»: pending-link и код; `/staff/auto-workshop-qc`: неизменяемый synthetic осмотр | реальная приёмка, полноценный наряд, запись/согласование |
| [Кладовщик](warehouse.md) | `/staff/warehouse-stocktake`: синтетические партии; `/staff/auto-demo-close`: закрытие резерва заказа | коммерческие закупки, реальный учёт |
| [Руководитель](manager.md) | `/staff` → «Автомобили (dev)»: проверка связи; `/staff/auto-estimates`: synthetic сметы; `/staff/auto-execution`: запуск работ; `/staff/auto-demo-close`: условная сверка и технический пакет | полноформатные KPI, управление СТО |
| [Клиент](client.md) | `/account/vehicles`: тестовое подтверждение; `/account/auto-estimates`: решение по версии synthetic сметы; `/account/auto-demo-close`: просмотр пакета | самостоятельная регистрация авто, история, оплата |
| [Механик](mechanic.md) | `/staff/auto-execution`: факт работ/получение деталей/завершение; `/staff/auto-workshop-qc`: независимый QC | выполнение ремонта, полная диагностика, выдача |
| [Бухгалтер](finance.md) | **Нет рабочего автомобильного сценария** | деньги, фискализация, документы |
| [Мобильное приложение](mobile.md) | **Нет рабочего приложения** | iOS/Android |

Эти маршруты предназначены только для закрытого dev-стенда. Для доступа нужна действующая сессия и права на конкретный объект/филиал; UUID не подтверждает доступ. При `403` не обходите права другим идентификатором; при `409` проверяйте состояние операции и повторяйте только по документированному безопасному сценарию. Для всех сценариев запрещены реальные ПДн, VIN и платежи. Независимая ручная QA-приёмка и production gate #119 ещё не пройдены.

## Как должна выглядеть инструкция

**Роль → Предусловия → Экран → Шаги → Ожидаемый результат → Ошибки/действия → Права → Проверено на версии.** Названия кнопок и ссылок должны совпадать с текущим интерфейсом, примеры — только синтетические.

Техническая документация находится в [общем индексе](../INDEX.md); правила актуальности — [DOCUMENTATION_POLICY.md](../DOCUMENTATION_POLICY.md). За разработку пользовательской базы знаний отвечают [#123](https://github.com/askarahodov/roboport/issues/123) и [#124](https://github.com/askarahodov/roboport/issues/124), публикация — [#125](https://github.com/askarahodov/roboport/issues/125).

## Доступная dev-инструкция по подтверждению автомобиля

Для QA и разработчиков доступно описание **закрытого синтетического процесса**, но не готовое руководство для реального автосервиса: [подтверждение автомобиля](../auto/VEHICLE_OWNERSHIP.md). Администратор и сотрудники ещё не могут создавать назначения в настоящем UI, а клиент не может самостоятельно добавлять автомобиль: эти шаги остаются `planned`.
