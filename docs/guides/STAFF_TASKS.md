# Карта рабочих операций БоксРитм — сотрудник, экран, проверка

> **Проверено по исходникам:** 10.11.2026 · #123 · текущий `main` после #477/#478. Версия для **закрытого synthetic HTTPS loopback dev**, не для эксплуатации с реальными VIN, ПДн и деньгами. Это карта **доступных разделов интерфейса**; сервер дополнительно проверяет текущую роль, организацию, филиал, объект и состояние операции. Сам факт наличия ссылки не даёт разрешения. [Полная ACL-матрица](ACCESS_AND_TEST_MATRIX.md) · [FAQ](FAQ.md).

## Как открыть справку в интерфейсе

В **«Рабочее место СТО»** (`/staff`) над рабочим списком доступны **«Быстрый старт»**, **«Навигатор операций»**, **«Ошибки 401/403/409 и помощь»**. Они работают и при отказе авторизации, не передавая cookie/UUID/CSRF-код в URL. После подтверждения серверной роли появляются **«Руководства моих ролей»** и отдельная **«Инструкция»** напротив каждого разрешённого раздела. Для `AUDITOR` есть [проверка доступов и журналов](ACCESS_AND_TEST_MATRIX.md), но дополнительных автомобильных операций роль сама по себе не открывает. Для `MANAGER` также доступна инструкция по управлению полномочиями; фактическое разрешение по организации проверяет backend.

Статусы: **current-dev** — работает лишь в синтетическом контуре; **planned** — работающего экрана/правовой операции нет; **legacy** — робототехника, не автомобильная инструкция. При **401** снова войдите через `/account/login`, при **403/404** проверьте организацию и полномочия без перебора чужих UUID, при **409** перечитайте текущую версию/остаток/журнал перед повтором; после неопределённого POST используйте прежний ключ через предусмотренную кнопку, если она есть.

## Бухгалтер и кассир — что реально есть и чего нет

**Доступ меню:** `FINANCE` либо `MANAGER` для `/staff/auto-demo-finance-report` и `/staff/auto-demo-close` согласно общему меню. **Backend разрешение остаётся независимым**: при отсутствии tenant/grant сервер может вернуть 403, даже если ссылка видна. [Подробное руководство](finance.md).

1. Откройте `/staff/auto-demo-finance-report`; выберите синтетическую организацию, филиал и период, если объект доступен, просмотрите **две раздельные категории условных событий**. Не объединяйте несопоставимые `CHARGE/CREDIT` и `SIM_PAYMENT/SIM_REFUND`.
2. `/staff/auto-demo-close` показывает техническую сверку/пакет **только при текущих серверных разрешениях и выполненных условиях**, но это не касса.
3. **planned / запрещено:** приём настоящих денег, эквайринг, фискальные чеки по 54-ФЗ, возвраты клиенту, бухгалтерская первичка, налоговый учёт, выдача автомобиля. В текущем контуре не проводите ни одного из этих действий.

## Администратор — назначение прав и границы

`/staff/auto-admin` сейчас указан в навигации `MANAGER`; фактические read/write grants, журнал событий и tenant scope проверяются **сервером**, где `ADMIN`-полномочия журнала не равны `MANAGER`-праву назначений. Не используйте видимость пункта меню как доказательство полномочий. В рамках доступных тестовых сценариев укажите UUID своей synthetic-организации, откройте журнал, при разрешённом staff-grant создайте назначение и при необходимости **«Отозвать» → «Подтвердить отзыв»**. При 403 данные чужой организации не отображаются, при 409 новое назначение не считается созданным. [Инструкция администратора](administrator.md). Production bootstrap и реальное управление персоналом **planned**.

### Закупка по дефициту WorkOrder (дополнение #443)

WAREHOUSE открывает `/staff/warehouse-supplier-orders`, вводит WorkOrder и партию, сравнивает **две синтетические** оферты по цене/сроку, заказывает только недостаток, записывает частичную поставку с неизменяемым источником. MANAGER может видеть реестр, а действующим WAREHOUSE grant создаётся документ; независимо от этого физический приход и cost valuation утверждаются другим MANAGER в `/staff/warehouse-receiving`. Отмена касается **только непоставленного остатка**. Ошибки 403/409/422, повтор с исходным ключом и отсутствие реального supplier EDI/оплаты подробно: [закупка по дефициту](../auto/SUPPLIER_PURCHASES.md). Нельзя считать эту операцию производственной бухгалтерией.

## Выработка механиков — current-dev (MANAGER, #448)

**Экран:** `/staff/auto-mechanic-productivity`.
Руководитель своего филиала указывает даты (1–31 день), нажимает
**«Рассчитать выработку»**, видит фактические минуты только технически
закрытых нарядов с независимым QC PASS и может выгрузить CSV.
При `403` проверить MANAGER/HANDOVER READ и организацию, при `409`
сократить диапазон, при `422` исправить даты. Данные только synthetic;
зарплата, реальные деньги и выручка не рассчитываются.
