# Сквозной сценарий «от записи до технической сверки» — шесть ролей БоксРитм

> **Статус: current-dev только для перечисленных шагов, исключительно synthetic.** Это сценарий одного тестового автомобильного заказ-наряда, а не утверждение о готовности СТО к работе с людьми, платежами или реальными автомобилями. Документ сверяет реальные React-экраны и тесты на 17.11.2026. **Юридические подписи, фискализация, реальная выдача и эксплуатация с ПДн — planned/blocked #119.** Ручная независимая приёмка QA #76 и визуальное утверждение #92 ещё не пройдены.

## Подготовить изолированный сценарий

1. QA/разработчик подготавливает **только искусственную** организацию, филиал, автомобиль, проверенную тестовую связь клиента, сотруднические назначения, пост, расписание, SKU и остаток по [synthetic cutover](../auto/SYNTHETIC_CUTOVER.md). Никаких живых VIN, ФИО, телефонов, фото клиента, денег, ключей доступа.
2. Используйте разные тестовые учётные записи: ADMIN организации, INTAKE филиала, MANAGER филиала, MECHANIC-исполнитель, **другой** MECHANIC-контролёр, WAREHOUSE и отдельный CASHIER/FINANCE. У каждого должен быть живой object/branch grant. Кнопка в меню **не заменяет** серверное право.
3. Для отдельного реального запуска QA записывает commit SHA, ссылку на CI, набор UUID синтетического fixture и результаты отрицательных запросов, но **не** сохраняет секрет выдаваемого клиенту кода. Доступный перечень и доказательства — [матрица ACL/тестов](ACCESS_AND_TEST_MATRIX.md) и [скриншоты](SCREENSHOT_EVIDENCE.md).
4. Вход на закрытом HTTPS loopback-стенде и [«Рабочее место СТО»](/staff) используются только при включённом synthetic auto API; отказ 404 при выключенном dev-режиме **ожидаем**. Клиентский кабинет — [«Мои автомобили»](/account/vehicles). В документации используйте относительные ссылки на страницы Docsify, чтобы ссылки проверялись CI.

| 7 | **WAREHOUSE**: `/staff/warehouse-receiving`, `/staff/warehouse-work-orders` | Принять синтетическую партию после независимого утверждения, проверить резерв WorkOrder; провести выдачу материалов по согласованной работе | Недостаток остатка, чужой филиал, повтор receipt/issue → 403/409; никакой физической отгрузки реального товара | `warehouse-receiving.spec.ts`, `warehouse-work-orders.spec.ts` |

Механик вносит «Фактические минуты», подтверждает получение деталей и завершает выполнение | Неподтверждённый материал, отменённая запись, не та смена или назначение → запрет; автор выполнения не делает независимый QC | `auto-work-execution.spec.ts`, `auto-assignments.spec.ts` |
| 9 | **Другой MECHANIC**: `/staff/auto-workshop-qc` | Проводит независимый QC: `FAIL` с причиной и последующий независимый `PASS` при устранении замечаний; старый FAIL остаётся в журнале | Самопроверка и QC после отзыва полномочий → 403; `PASS` **не** разрешает выдачу | `auto-workshop-qc.spec.ts`, `test_pg_auto_workshop_qc_http.py` |

**Нельзя заменять чужую учётную запись совмещением ролей.** Когда операция требует независимого подтверждения, проверяющий должен отличаться от исполнителя и иметь собственный действующий grant; HTTP выполняет повторную проверку, даже если frontend показывает кнопку.

## Контрольная выгрузка приёмочного акта — current-dev, но без подписи

1. Сотрудник INTAKE либо клиент с действующим правом на **исходный** заказ открывает `/staff/auto-intake-act` или `/account/auto-intake-act` со своими синтетическими UUID.
2. На странице одной сохранённой версии сверяет зоны, комплектность, изображение, SHA-256 и возможное техническое решение клиента. Нажимает **«Скачать проверяемый архив версии №N (ZIP)»**.
3. На своём **тестовом** устройстве открывает `manifest.json` и сравнивает `sha256` каждого `photos/N.png` с `files[].sha256`. Архив содержит **одну версию** и не доказывает юридического подписания.
4. После отзыва связи клиент не должен скачивать ZIP (403); уже сохранённый файл останется на устройстве. Не отправлять ZIP в реальные сервисы, чаты и хранилища: даже синтетические фото могут нести непроверенное содержание. Подробнее — [правила хранения и экспортирования](../auto/WORKSHOP_OPERATIONS.md).

**Контроль:** `apps/web/e2e/auto-intake-act.spec.ts` и `tests/integration/test_pg_auto_intake_act_http.py`; изменения выпущены PR #506, [CI 5/5](https://github.com/askarahodov/roboport/actions/runs/44041537135). Это техническая выгрузка, не signed PDF и не согласие на выдачу.

## Если сценарий остановился

| Симптом | Безопасное действие | Чего не делать |
|---|---|---|
| `401` или истёкшая сессия | Заново войти через обычный экран; после входа повторить **чтение** состояния | Не обходить cookie/session защиту |
| `403` или закрытый объект | Проверить собственные назначения, филиал и отзыв прав у ADMIN/MANAGER; при раскрытых данных прекратить работу | Не перебирать UUID чужих автомобилей и заказов |
| `404` на dev API | Проверить, что запущен **разрешённый synthetic** контур | Не включать synthetic API на production |
| `409` при версии, бронировании, партии или ревизии | Обновить журнал/версию и повторно оценить действие; для неопределённого POST пользоваться исходным request key, если UI это поддерживает | Не придумывать новый ключ лишь чтобы продублировать запись |
| `422` при фото/данных | Исправить конкретное поле, проверить лимиты и фото PNG, не прятать ошибки | Не отключать backend-валидацию |
| `429` при доказательстве связи | Дождаться разрешённого серверного периода; при утрате кода — предусмотренный однократный перевыпуск | Не увеличивать число попыток перебором |
| Сеть упала после записи | Перечитать авторизованный журнал; для неясного результата повторить **тот же запрос** и ключ, где предусмотрено | Не считать платежи, согласия или документы успешными без ответа |

## Проверки готовности и пределы

- **Автоматически:** API, PostgreSQL 17, Web, Playwright, Windows CMD — см. точный run текущего PR; Docsify навигация/маршруты тестируется в `apps/web/e2e-docs/portal.spec.ts` и ссылки проверяет `scripts/check_docs_links.py`.
- **Ручная независимая QA (не пройдена):** разные сессии шести ролей, 390/1280/1440, light/dark/auto, клавиатура и фокус, 403 после отзыва, устаревшая ревизия, скриншоты без PII. [Протокол](SCREENSHOT_EVIDENCE.md).
- **Production blocked:** права на реальные документы, согласия, фото/удаление, объектное хранилище/AV, ЭП, фискализация, пользовательский onboarding и выдача остаются открытыми по #119, #123, #439, #441–#446. Отдельные существующие функции не превращают продукт в готовый production ERP.
